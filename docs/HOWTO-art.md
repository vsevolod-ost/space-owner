# Art guide

For the artists: the screen size, the pixel rules, every picture the game uses now with its size,
how a character sheet is laid out, and how to hand art over. You do not need to touch code; the
last section says what to tell the programmer.

## Screen and pixels

- The game is drawn at **640×360 pixels** and scaled up by a **whole** factor to fit the window:
  ×2 at 1280×720, ×3 at 1920×1080 (black margins fill the rest). One pixel of your art is always
  an exact square of screen pixels. Draw at 640×360 scale: a picture as wide as the screen is
  640 px wide.
- **Whole pixels only.** No sub-pixel detail, no blurry edges, no anti-aliasing against a
  background colour you do not know; the game shows pixels without smoothing.
- Transparency is either fully on or fully off at the edges of sprites (no soft shadows made of
  half-transparent pixels unless you want them visible as such).
- The game's font is Press Start 2P on an 8×8 grid; text is 8 or 16 px high. The game draws
  all text itself: **never bake text into buttons, panels or other UI art**, so that a renamed
  button is a code change, not a new picture.
- Palette: 16 base colours with 16 shades each, see [palette.md](palette.md) (to be filled in by
  the artists).

## Character sheets

One PNG per character, frames of **32×48 px** in a grid of **4 rows × 4 columns** (128×192):

|                  | frame 0 | frame 1 | frame 2 | frame 3 |
| ---------------- | ------- | ------- | ------- | ------- |
| row 0: **down**  | idle    | walk    | walk    | walk    |
| row 1: **left**  | idle    | walk    | walk    | walk    |
| row 2: **right** | idle    | walk    | walk    | walk    |
| row 3: **up**    | idle    | walk    | walk    | walk    |

- Frame 0 of a row is the character standing still facing that way; frames 1-3 are the walk
  cycle, played in a loop at 8 frames per second.
- The character's **feet stand at the bottom centre** of the frame: the game puts that point on
  the floor and sorts characters by it (who is in front). Leave little or no empty space under
  the feet.
- Characters walk in 8 directions, but there are only 4 rows: the dominant axis picks the row;
  on an exact diagonal the current facing is kept if it is one of the two, else the horizontal.
- A different frame size (say 24×32 or 48×64) or another number of walk frames is fine: tell
  the programmer, it is one line per character (`src/assets/spritesheets.ts`,
  `src/content/characters.ts`). Keep every frame of one character the same size.

## Portraits

**48×48 px**, one per speaking character, shown at the left of the dialogue window next to the
speaker's name. Face and shoulders; it sits on the window's panel background. Expressions
(mimicry) are extra portraits of the same size (`portraits/captain-angry.png`): a dialogue line
can name its own portrait, so once the file is registered the writer picks it per line
([HOWTO-dialogue.md](HOWTO-dialogue.md)).

## UI art

- **Panel** `ui/panel.png`, **24×24**, drawn as a 9-slice with a **border of 8 px**: the four
  8×8 corners are drawn as they are, the edges between them stretch along one axis and the 8×8
  centre stretches in both. Every panel in the game (dialogue window, menus, settings, the
  navigation panel) is this one picture stretched. The centre may be partly transparent so the
  game shows through (the placeholder is fully opaque). A different border width needs a
  one-line change in `src/ui/theme.ts` (`panelBorder`).
- **Buttons** `ui/button-{normal,hover,pressed}.png`, **160×36**, three states of the same
  button, **no text**. Buttons of other sizes (the small "-" / "+" in the settings panel are
  24×20) stretch the same pictures as a 9-slice with a **4 px border** (`buttonBorder` in
  `src/ui/theme.ts`), so keep the outer 4 px of the button art as its frame and the middle
  plain.

## Location backgrounds

- One location = **one picture**: the whole room or area, drawn with its walls, furniture and
  floor. The game draws it as one image; walls are marked separately in the map editor (Tiled)
  by the programmer, so draw the floor where the characters can walk clearly.
- **Any size that fits the design.** A location as big as the screen (640×360) does not scroll;
  a larger one scrolls with the hero. Prefer multiples of 16 px (the map grid); if not, the map
  rounds the tile count up and nothing breaks (540 px tall = 33.75 tiles, the map is 34).
- Characters are 48 px tall: doors, corridors and furniture should be drawn at that scale.
- Doors and passages: say where they are (or keep them where the placeholder has them), since
  the map's door zones must match.

## Delivering art

1. **Format:** PNG, RGB or RGBA, no colour profile tricks, exact size from the table.
2. **Name:** the placeholder's name to replace it (`sprites/hero.png`); a new file gets a
   kebab-case name in the matching folder: `sprites/npc-<character>.png`,
   `portraits/<character>.png`, `images/locations/<location>.png`, `ui/<what>.png`.
3. **Where:** into `public/assets/<folder>/` in a branch and a pull request
   ([CONTRIBUTING.md](CONTRIBUTING.md)), or hand the files to the programmer.
4. **What to tell the programmer:** for a replaced placeholder, nothing - same name and size means
   no code change. For a **new** file: its path, what it is, its size (and frame size for a
   sheet); the programmer adds it to the registry (`src/assets/images.ts` or
   `src/assets/spritesheets.ts`), and for a new location or character to its content file.

**Do not run `tools/placeholders.py` after real art is in.** The script rewrites every
placeholder file it knows about and would overwrite your art with a placeholder of the same name.
If it happens, `git status` shows the files and `git checkout -- <file>` restores them.
